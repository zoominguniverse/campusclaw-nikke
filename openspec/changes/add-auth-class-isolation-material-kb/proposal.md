## Why

CampusClaw 目前需要建立真实互联网应用的安全边界和教学材料入口：用户必须先认证，数据必须按班级隔离，教师上传的材料还要能够进入本班知识库。现在若缺少这些约束，前端隐藏按钮无法阻止越权调用，材料也无法形成可查询的知识库记录，无法满足后续 AI 教学能力的可靠基础。

## What Changes

- 增加账号密码登录，覆盖教师和学生角色，并保护需要认证的页面与接口。
- 增加基于角色的服务端授权：学生不能上传教学材料，直接调用上传接口也必须被拒绝。
- 将班级作为服务端数据边界：用户访问其他班级材料时必须被拒绝，不能仅依赖前端隐藏或过滤。
- 增加教师教学材料上传流程，将上传材料写入知识库，并能在本班材料列表中查询到记录。
- 建立本课所需的核心数据骨架：班级、用户、教学材料/讲义、作业、助手和技能六类结构；预置 A/B 班各一名教师、两名学生及可区分的示例材料，便于演示教师上传、学生只读和跨班隔离。
- 密码仅以安全哈希形式存储，禁止明文密码；密钥仅从服务端环境变量读取。
- 提供 Docker Compose 启动方式，固定开放三个课程实践端口：前端 `5173`、Flask API `8080`、PostgreSQL `5432`；API 提供 `GET /health` 健康检查接口。
- 使用 PostgreSQL 持久化用户、班级、材料、知识库和预置数据，不再使用 SQLite。
- 补充最小可运行交付物的文档与配置约定，包括 README 的价值/场景/非目标说明、依赖和应用入口、`Dockerfile`、`docker-compose.yml`、`.env.example` 以及首次启动初始化数据的约定。

## Non-Goals

- 本课不实现基于知识库的检索问答或引用生成能力；本变更只保证材料能够安全入库并形成可查询记录。
- 本课不实现对话助手、智能体编排、工具调用或其他完整 AI 助手能力。
- 本课不实现作业提交、自动批改、教师改分或错题讲解业务。
- 本课不实现 SSO、第三方身份提供商接入、组织级账号同步或复杂的账号生命周期管理。
- 本课不实现生产级高可用（HA）、多副本部署、跨地域容灾、自动扩缩容或云厂商托管存储。
- 本课不实现多学校/多租户、OAuth/OIDC、短信或邮件登录，也不实现 Kubernetes、完整 CI/CD 或生产级多副本运维；Compose 仅用于本地和课程演示。

## Capabilities

### New Capabilities

- `user-authentication-and-authorization`: 账号密码登录、登录态、受保护页面、教师/学生角色权限和密码安全存储。
- `class-data-isolation`: 以班级为服务端数据边界，对材料访问和相关接口执行跨班级拒绝。
- `material-knowledge-base-ingestion`: 教师上传教学材料、知识库写入、本班材料列表查询和上传记录可见性。
- `service-runtime`: Docker Compose 启动契约、服务端密钥配置和 `GET /health` 健康检查。

### Modified Capabilities

无。当前项目没有既有规格文件。

## Impact

- 新增用户、角色、班级、材料和知识库记录相关的数据模型及持久化逻辑。
- 新增登录、鉴权、材料上传、材料列表和健康检查 API，并对受保护页面增加未登录跳转行为。
- 需要服务端会话或令牌方案、密码哈希依赖、文件/材料存储与知识库写入适配层。
- 需要 Docker Compose、前端/API/数据库三服务、PostgreSQL 数据卷、环境变量配置和健康检查配置；具体端口和连接方式在 `design.md` 中确定。
- 需要补充认证、越权、跨班级访问、材料写入、密钥泄露防护、容器启动和健康检查测试。
